Pointer nedir?

Pointer, başka bir nesnenin bellek adresini tutan değişkendir. p, q'nun adresini tutuyorsa “p, q'yu işaret ediyor” denir. q bellekte 100 adresindeyse p'nin değeri 100'dür.

p @ 200100
──►
q @ 10075
dataType *identifier;      // genel sözdizimi
int *p;   char *ch;          // * değişken adına yapıştırılır (tercih)

int x = 75;
cout << x;     // 75
cout << &x;    // x'in adresi, ör. 0x7fff8164
OperatörAdıNe yapar
&xAdres operatörü (address-of), tekliOperandının adresini döndürür
*pDereferencing / indirection (dolaylı erişim), teklip'nin gösterdiği nesneye erişir. İkili çarpma * ile karıştırma.
Tuzak: Birden fazla pointer tanımlarken her isme ayrı * gerekir. 
int *iPtr1, *iPtr2;      // ikisi de int*
double *iPtr3, iPtr4;    // iPtr3 → double*,  iPtr4 → düz double!

Başlatma ve atama: Pointer tanımlanırken başlatılabilir (int *iPtr = 0; char *s = NULL;). Atama (=) yalnızca aynı temel tipteki pointer'lar arasında tanımlıdır:

int x, *xp, *ip;
xp = &x;     // xp, x'i gösterir
ip = xp;     // ip de artık x'i gösterir

Temel tip (base type), işaret edilen nesnenin nasıl yorumlanacağını belirler (int *p → gösterdiği yer 4 baytlık int olarak okunur) ve pointer aritmetiğini de tanımlar.

Pointer aritmetiği

Sadece dört işlem desteklenir: +, -, ++, --. İşlem, temel tipin boyutu kadar yapılır: p++, “bir sonraki nesneyi göster” demektir.

Tanımp = 1000 iken p++ sonrasıNeden
char *p1001sizeof(char) = 1
int *p1004sizeof(int) = 4
float *p1004sizeof(float) = 4
double *p1008sizeof(double) = 8

Slayttaki çıktı: sizeof(p) = 4 (32 bit sistem; pointer'a 4 bayt ayrılır). 64 bit sistemde 8 olur, ama sınavda slayttaki değeri (4) esas al.

Pointer karşılaştırma

  • p == NULL ya da kısaca !p: NULL, false olarak değerlendirilir.
  • p == q: aynı nesneyi mi gösteriyorlar?
  • *p == *q: gösterdikleri değerler eşit mi? Aynı nesne olmak zorunda değil.

Diziler ve pointer'lar

Dizinin adı, ilk elemanın adresidir. Diziler ve pointer'lar çoğu durumda birbirinin yerine kullanılabilir.

int num[4] = {1,2,3,4}, *p;
p = num;          // p = &num[0] ile aynı
cout << *p;       // 1
++p;
cout << *p;       // 2

char myString[] = "This is a string";
char *str = myString;
for (int i = 0; str[i]; i++)   // '\0' (null) gelince durur
    cout << str[i];            // pointer [] ile indekslenebilir
Tuzak: Dizi adı bir pointer gibi davranır ama değeri değiştirilemez; her zaman aynı konumu gösterir (num++ hatadır). Pointer değişkenine ise 4 bayt ayrılır ve başka nesneyi gösterecek şekilde yeniden atanabilir.

Pointer dizisi: int *iPtrs[10]; → 10 tane int pointer'ı. iPtrs[0] = &num; cout << *iPtrs[0];

Fonksiyona pointer geçirme: Pointer değerle (by value) ya da referansla (by reference) geçirilebilir. Her iki durumda da gösterdiği nesne değiştirilebilir. Pointer'ın kendisi ise yalnızca referansla geçirildiğinde değiştirilebilir.

Dinamik bellek çalışma zamanında ayrılır; sınırlı kaynağı verimli kullanır; stack, queue, bağlı liste, ikili ağaç gibi dinamik yapılar için kullanılır ve ihtiyaç bitince program çalışırken serbest bırakılmalıdır.

new ve delete

  • new: C'deki malloc()'un yerini alır. Heap'ten blok ayırır, ilk baytın adresini döndürür. Başarısız olursa exception fırlatır (eski derleyicilerde NULL döner).
  • delete: C'deki free()'nin yerini alır. Sadece new ile ayrılmış belleği serbest bırakır.
int *iPtr = new int;          // 4 bayt
double *dPtr = new double[20]; // 20 × 8 = 160 bayt
int *a = new int(100);         // 4 bayt, başlangıç değeri 100

delete iPtr;
iPtr = NULL;                   // iyi uygulama: pointer'ı null yap

double *dptr = new double[SIZE];   // SIZE derleme zamanında bilinmek zorunda değil
...
delete [] dptr;                    // dizi için köşeli parantez şart
Bellek sızıntısı (memory leak): Fonksiyon bitince yerel değişkenler (numElements, ptrArr) yok olur, dinamik dizinin adresi kaybolur, ama dizi yok edilmez. new o alanı hâlâ kullanılıyor sayar ve tekrar veremez. Sızıntı kalıcı değildir, program durunca biter. Sürekli sızdıran program heap'i tüketebilir.
void foo() {
    int numElements;  cin >> numElements;
    float *ptrArr = new float[numElements];
    // ... dizi işlenir
}   // delete [] ptrArr yok → MEMORY LEAK

new/delete ile yaygın hatalar

Bellek yönetiminde her dinamik parça için bir sahip (owner) belirlenir; ihtiyaç kalmayınca delete etmek sahibin sorumluluğudur.

  1. Dangling pointer (sarkan pointer): delete sonrası o belleği gösteren pointer'ı kullanmak.
  2. Memory leak: artık kullanılmayan belleği geri vermemek.
  3. new ile ayrılmamış bir belleğe delete uygulamak.
  4. Dinamik diziyi silerken []'yi unutmak (delete p yerine delete [] p).

Sığ (shallow) ve derin (deep) kopya

  • Shallow copy: iki pointer aynı belleği/aynı veriyi gösterir. second = first; sonrası delete [] second; yapılırsa first da artık silinmiş alanı gösterir (dangling).
  • Deep copy: her pointer'ın kendi verisi vardır; yeni alan ayrılıp elemanlar tek tek kopyalanır.

Derleyicinin verdiği varsayılan copy constructor üye üye kopyalar, bu da pointer üyelerde sığ kopyaya yol açar. Çözüm kendi copy constructor'ını yazmaktır:

className(const className& otherObject);

Dizi genişletme (array expansion), adım adım

Dolu dinamik diziye (ptr, size = 4: 5 7 4 2) yer açmak için:

int *temp = new int[size * 2];   // 1) iki kat büyük yeni dizi
for (int i = 0; i < size; i++)   // 2) elemanları kopyala
    temp[i] = ptr[i];
delete [] ptr;                   // 3) eski diziyi sil
ptr = temp;                      // 4) ptr yeni diziyi göstersin
size = size * 2;                 // 5) size = 8
Tuzak: Sıra önemli. delete [] ptr kopyalamadan önce yapılırsa veri kaybolur. ptr = temp silmeden önce yapılırsa eski dizinin adresi kaybolur (leak). Sonuçta aynı isim (ptr) daha büyük diziyi gösterir.

Veri yapısı, ADT, algoritma (Ders 1 sonu)

  • ADT (Soyut Veri Tipi): Bir nesnenin ve üzerindeki işlemler kümesinin matematiksel tanımı. Uygulamayı belirtmez, sadece arayüzdür.
  • Algoritma: Bir problemi çözmek için adım adım sürecin yüksek seviyeli, dilden bağımsız açıklaması.
  • Veri yapısı: Bir ADT'yi gerçekleştiren algoritmalar kümesi. Bir ADT'nin çok sayıda veri yapısı olabilir. Örneğin Dictionary ADT: liste, ikili arama ağacı, AVL, Splay, Red-Black ağacı, hash tablosu.
  • Neden bu kadar çok veri yapısı var? Gerilimler yüzünden: zaman ↔ alan, performans ↔ zarafet, genellik ↔ sadelik, bir işlemin performansı ↔ diğerininki.
  • Dizi tabanlı yapılarda erişim çok hızlıdır (taban adres + ofset). Ama bitişik bellek zorunluluğu yüzünden ekleme/silme maliyetlidir.

List ADT

Soyutlama: temel özelliklere odaklanmak için uygulama ayrıntılarını gizlemek. Arabayı direksiyon ve pedallarla (arayüz) kullanırsın, motorun termodinamiğini (uygulama) bilmen gerekmez.

ADT, kullanıcının bakış açısından davranışla tanımlanan matematiksel modeldir. Üç unsuru vardır:

  1. Saklanan veri
  2. İzin verilen işlemler
  3. İşlemlerin kısıtları (ön koşul / son koşul)

Liste: elemanlardan oluşan sonlu ve sıralı bir dizi: ⟨a₀, a₁, …, aₙ₋₁⟩. Boş liste ⟨ ⟩ şeklinde gösterilir.

Tuzak: Buradaki “sıralı” (ordered), her elemanın bir konumu olduğu anlamına gelir. Değerlere göre küçükten büyüğe sıralı (sorted) demek değildir.
  • İlk konum 0, son konum n − 1.
  • Hiç eleman yoksa boş (empty). O anki eleman sayısı uzunluk (length).
  • Başı head, sonu tail.
  • İşlemler eleman tipinden bağımsız tanımlanır: int listesi, char listesi, maaş kaydı listesi, hatta liste listesi olabilir.

Gerçekleştirimler: 1) dizi tabanlı liste (a: statik dizi, b: dinamik dizi), 2) bağlı liste. Hepsi aynı List ADT'sini kullanır ama alan/zaman maliyetleri farklıdır.

Arayüz (soyut sınıf) kodu

class List {
public:
    virtual ~List() {}                        // sanal yıkıcı
    virtual void   add(int i, double x) = 0;  // 0 <= i <= size
    virtual double get(int i) const = 0;      // 0 <= i <  size
    virtual double set(int i, double x) = 0;  // 0 <= i <  size
    virtual double remove(int i) = 0;         // 0 <= i <  size
    virtual int    size() const = 0;
    virtual bool   isEmpty() const = 0;
};
  • = 0 → saf sanal (pure virtual) fonksiyon. List bir soyut temel sınıftır; ne yapılacağını (WHAT) söyler, nasıl yapılacağını (HOW) söylemez. Türetilmiş sınıflar için bir sözleşme görevi görür.
  • Sanal yıkıcı, türetilmiş sınıfların doğru temizlenmesi için gereklidir.
  • ArrayList / LinkedList List'ten miras alır (kalıtım). Aynı fonksiyon adları polimorfizm sağlar: program List referansıyla her tür listeyi kullanabilir.
Tuzak: add için i == size geçerlidir (sona ekleme). get/set/remove için i == size geçersizdir.
class ArrayBasedList : public List {
    double* elements; int capacity; int currentSize;
    void resize(int newCapacity) {
        double* newArray = new double[newCapacity];
        for (int i = 0; i < currentSize; i++) newArray[i] = elements[i];
        delete[] elements;
        elements = newArray;  capacity = newCapacity;
    }
public:
    ArrayBasedList() { capacity = 10; currentSize = 0; elements = new double[capacity]; }
    ~ArrayBasedList() { delete[] elements; }   // sızıntıyı önler
};

Diğer ADT işlemleri: konum işlemleri (add, remove, set, get), durum sorguları (size, isEmpty), arama ve toplu işlemler (indexOf, clear).

C++ dizilerinin ve vektörlerinin sorunları

Dizi

  1. Sabit boyut: sonradan değişmez. Büyük tahmin bellek israfıdır, küçük tahmin taşma riskidir.
  2. Sınır denetimi yok: int arr[5]; cout << arr[10]; → tanımsız davranış (çökme ya da bellek bozulması).
  3. El ile bellek yönetimi: new[] → delete[] unutulursa sızıntı olur.
  4. Dinamik boyutlandırma desteği yok: yeni dizi al, kopyala, eskiyi sil.
  5. Yardımcı fonksiyon yok: ekleme/silme/arama el ile yazılır.

Vektör

  1. Kapasite aşılınca genelde iki katına çıkar ve tüm elemanlar yeni yere kopyalanır, bu pahalıdır.
  2. Ortaya ekleme/silme kaydırma gerektirir; bağlı listeden yavaştır.

Dizi kullan: boyut derleme zamanında biliniyorsa, bellek kısıtı sıkıysa, ek yüksüz hızlı rastgele erişim gerekiyorsa. Vektör kullan: boyut dinamikse, push_back(), erase(), size() gerekiyorsa, otomatik bellek yönetimi isteniyorsa.

Bağlı liste

Her eleman (düğüm / node) kendi bellek bloğunda durur ve pointer'larla zincirlenir. Elemanların bellekte bitişik olması gerekmez. Mantıksal sıra, fiziksel sıradan bağımsızdır.

head─►
0xF6510alice │ •
─►
0xF7100bob │ •
─►
charlie │ ∅

Benzetme: el ele tutuşan insanlar. Ekleme: önceki kişi yeni kişinin elini, yeni kişi de sonrakinin elini tutar, kaydırma yok. Çıkarma: önceki kişi doğrudan sonrakinin elini tutar.

  • Düğüm: veri + bir veya daha fazla pointer. Bağlı liste, ağaç ve grafların yapı taşıdır.
  • Doğrusal: her düğümün tam bir öncülü ve bir ardılı vardır (ilkinin öncülü, sonuncunun ardılı olmayabilir).
  • Öz-referanslı (self-referential): düğüm aynı türden başka bir düğüme (hatta kendisine) referans verir. next'in türü Node*'dır.
  • head: her zaman ilk düğümü gösterir; doğrudan indeksleme olmadığı için tek giriş noktasıdır. head == nullptr ise liste boştur. Son düğümün next'i nullptr'dır.
  • Tek yönlü (singly): sadece next. Çift yönlü (doubly): next ve prev.
  • Avantajları: dinamiktir (büyür/küçülür), bitişik değildir, ortaya ekleme pointer güncelleyerek yapılır, resize maliyeti yoktur.
class Node {
public:
    string name;   // veri
    Node* next;    // sonraki düğüm
    Node(string nodeName) { name = nodeName; next = nullptr; }
};
Node* front  = new Node("alice");
Node* second = new Node("bob");
front->next = second;      // alice → bob → nullptr
Slaytın tavsiyesi: Bağlı liste kodu yazarken mutlaka şekil çiz. Çizmezsen pointer sırasını karıştırmak çok kolaydır.

new boş alanı nasıl bulur?

  1. Heap yöneticisi boş blokları bir serbest liste (free list, bağlı liste) olarak tutar ve yeterince büyük bir blok arar.
  2. Belleği o blokta ayırır.
  3. Pointer'ı döndürür.

Ardışık iki new neden bitişik değildir? Üç nedeni var: heap parçalanması, bellek hizalama ve dolgu (bloklar 8/16/32 bayta yuvarlanır) ve işletim sisteminin ayırmaları ayrı bellek sayfalarına koyabilmesi.

LinkedList kodları (ezberle)

Kurucu: head = nullptr; count = 0;. Kullanıcı sadece public metotları görür; iç yapı gizlidir. Buna bilgi gizleme (information hiding) denir.

insertFront: başa ekle

void insertFront(string val) {
    Node* p = new Node(val);   // 1) yeni düğüm
    p->next = head;            // 2) yeni düğüm eski ilk düğümü göstersin
    head = p;                  // 3) head yeni düğümü göstersin
    count++;
}
Tuzak: 2 ve 3. satırlar yer değiştirirse (head = p; p->next = head;), düğüm kendini gösterir ve listenin geri kalanı kaybolur. Liste boşsa p->next nullptr olur, bu doğrudur.

Örnek: boş listeye insertFront("a"), ("b"), ("c") → print çıktısı c b a (başa ekleme sırayı ters çevirir).

deleteFirst: ilk düğümü sil

void deleteFirst() {
    if (head != nullptr) {     // boşsa hiçbir şey yapma
        Node* t = head;        // 1) eski head'i hatırla
        head = head->next;     // 2) head'i bir ileri taşı
        delete t;              // 3) eski düğümü serbest bırak
        count--;
    }
}

t olmadan eski düğümün adresi kaybolur ve silinemez (leak). delete t sonrası t geçersiz adresi gösterir ama yerel değişken olduğu için sorun değildir.

print: dolaşma (traversal)

void print() const {
    Node* walk = head;
    while (walk != nullptr) {
        cout << walk->name << " ";
        walk = walk->next;
    }
}
Tuzak: Koşul walk->next != nullptr olursa son eleman yazılmaz, boş listede de nullptr erişimi olur. Dolaşmak için head'i değil geçici pointer'ı ilerlet; head'i kaybedersen listeyi kaybedersin.

Diğer metotlar: append (sona ekle), search (değer ara), deleteNode(val) (ilk eşleşeni sil), size().

Yığın nedir?

Ekleme ve çıkarmanın her zaman aynı uçtan (top / üst) yapıldığı sıralı koleksiyon. Karşı uç taban (base); tabana yakın elemanlar en uzun süredir yığında olanlardır. Kural LIFO: Last-In First-Out (son giren ilk çıkar). Diğer adı push-down list / push-down stack. Örnek: yemekhanedeki üst üste tepsiler.

İşlemNe yapar
pushÜste yeni eleman ekler
popÜstteki elemanı çıkarır
isEmptyBoş mu?
isFullDolu mu?
returnTopÜstteki elemanı söyler (çıkarmaz)

Slayt örneği: push 8, 860, −60, 10 → üstte 10. Silme sırası: 10, −60, 860, 8.

Tuzak: Boş yığına pop uygulanmaz. Önce isEmpty() ile kontrol et (underflow). Yığın kavramı tektir ama uygulama biçimleri farklı olabilir (dizi, bağlı liste).

Yığın uygulamalarının 4 kategorisi

  1. Tersine çevirme (reversing): verinin sırasını ters çevirmek.
  2. Ayrıştırma (parsing): parantezlerin doğru eşleşip eşleşmediği.
  3. Kullanımı erteleme (postponing): infix → postfix dönüşümü ve postfix değerlendirme.
  4. Geri izleme (backtracking): labirent, N-Vezir. Yollar arasında seçim yapıp gerekince geri dönmek.

Infix → postfix algoritması (yığınla)

  1. İşlenen (harf/sayı) → doğrudan çıktıya.
  2. İşleç geldiğinde: yığın boşsa push et. Değilse, gelen işlecin önceliği yığının tepesindekinden küçük veya eşit olduğu sürece tepedekini pop edip çıktıya yaz. Tepe ( olunca dur. Sonra gelen işleci push et.
  3. ( → push. Okunurken en yüksek öncelikli, yığının içindeyken en düşük önceliklidir; her işleç onun üstüne konur.
  4. ) → ('ya kadar her şeyi pop edip çıktıya yaz; ('yı at. Parantezler çıktıya yazılmaz.
  5. İfade bitince yığında kalanları sırayla pop edip çıktıya yaz.

N-Vezir problemi (geri izleme)

N×N tahtaya N vezir: aynı satır, sütun ya da köşegende iki vezir olamaz.

  • Yığın, yerleştirilen her vezirin (satır, sütun) kaydını tutar. filled (dolu) tamsayısı kaç satırın dolu olduğunu tutar.
  • Çakışma yoksa → filled++. filled == N ise çözüm bulundu. Değilse sonraki satıra geç ve 1. sütundan başla (push).
  • Çakışma var ve sağa kayacak yer varsa → veziri sağa kaydır, yığının tepesindeki kaydı güncelle.
  • Çakışma var ve yer yoksa → geri izle: pop, filled−−. Sağa kaydırılabilecek bir satır bulana kadar tekrarla.
İleri giderken her zaman ilk sütundan başlanır. Geri izlerken kalınan yerden devam edilir; 1. sütuna dönülmez. Pop sırasında yığın tamamen boşalırsa ilk vezirin de yeri bitmiştir, yani çözüm yoktur.

4-Vezir izi (slayt): (1,1),(2,3) → 3. satır yok → geri izle (2,4) → (3,2) → 4. satır yok → (3,3),(3,4) yok → (2,?) yok → (1,2),(2,4),(3,1),(4,3) → çözüm.

Dizi ile yığın

En basit gerçekleştirme dizi kullanmaktır. Dezavantajı: boyut önceden belirlenmelidir. Dizi yığının kendisi değil, saklandığı alandır. Mevcut konumu (top) tutmak için ek bir değişken gerekir.

int stack[MAX]; int top = -1;
void push(int x){ if (top == MAX-1) /* overflow */; else stack[++top] = x; }
int  pop()      { if (top == -1)    /* underflow */; else return stack[top--]; }

Ders 5 · Queue

Kuyruklar: FIFO, doğrusal ve dairesel dizi

Tanımİzleme örneğiDoğrusal diziSorunDairesel6 yöntem

Kuyruk nedir?

Elemanların arkadan (rear) eklendiği, önden (front) çıkarıldığı liste. Kural FIFO: First-In First-Out (ilk giren ilk çıkar), “ilk gelen ilk hizmet alır”. Süpermarket, banka sırası. Adil işlem sırası sağlar.

Bilgisayardaki uygulamaları: tek işlemcide işlerin (jobs) sıraya alınması, yazdırma kuyruğu (print spooling), ağda bilgi paketlerinin sıralanması.

İşlemNe yapar
enqueue(q, x)x'i kuyruğun sonuna (rear) ekler
x = dequeue(q)Öndeki elemanı çıkarır ve döndürür
isEmpty(q)Boş mu?
isFull(q)Yeni eleman için yer var mı?
Yığın ile fark: Yığında ekleme ve silme aynı uçtan (top) yapılır. Kuyrukta iki farklı uçtan yapılır (rear'a ekle, front'tan çıkar).

Slayttaki izleme örneği

enqueue(q, 9); enqueue(q, 10); enqueue(q, 50);
x = dequeue(q); Print(x);        // 9
enqueue(q, 20); enqueue(q, -40);
x = dequeue(q); Print(x);        // 10
enqueue(q, 40);
x = dequeue(q); Print(x);        // 50
enqueue(q, 30);

Çıktı: 9, 10, 50 · Son kuyruk (front → rear): 20, −40, 40, 30

Doğrusal dizi ile kuyruk

#define MAXQUEUE 20
struct QueueRec { int count; int front; int rear; float entry[MAXQUEUE]; };
typedef struct QueueRec Queue;

void initializeQueue(Queue* q) { q->front = 0;  q->rear = -1; }

BOOL queueEmpty(const Queue* q) { return q->rear < q->front; }

void enqueue(Queue* q, float item) {
    if (queueFull(q)) { fprintf(stderr,"Queue is full\n"); exit(1); }
    q->rear++;                    // ÖNCE rear artar
    q->entry[q->rear] = item;     // SONRA yazılır
}
float dequeue(Queue* q) {
    if (queueEmpty(q)) { fprintf(stderr,"Queue is empty\n"); exit(1); }
    float item = q->entry[q->front];   // ÖNCE okunur
    q->front++;                         // SONRA front artar
    return item;
}
Başlangıç: rear = -1, front = 0
Boş: rear < front
Eleman sayısı: rear − front + 1
Her enqueue'da rear, her dequeue'da front bir artar.
Ekleme sırasında taşma (overflow) kontrol edilir; dizi doluyken ekleme yapılırsa taşma olur.
Tuzak: entry[MAXQUEUE] dizisinde son geçerli indeks MAXQUEUE − 1'dir. rear −1'den başladığı için kuyruk rear == MAXQUEUE − 1 olduğunda dolar. (Slayttaki rear==MAXSIZE kontrolüne dikkat: indeks açısından doğru sınır MAX−1.)

Doğrusal kuyruğun sorunu

rear sürekli artar. Çıkarılan elemanların yerleri tekrar kullanılmaz. Sonuçta kuyrukta çok az eleman olsa bile (hatta kuyruk boşken bile) rear dizinin sonuna geldiği için yeni eleman eklenemez. Dizinin çok büyük olması gerekir.

Çözüm: diziyi düz çizgi değil dairesel (circular) düşün: indeks 0, son indeksin hemen ardından gelir.

Dairesel (circular) kuyruk

İndeksi bir artırmanın 3 eşdeğer yolu:

i = ((i + 1) == max) ? 0 : (i + 1);        // 1) ternary
if ((i + 1) == max) i = 0; else i = i + 1;  // 2) if-else
i = (i + 1) % max;                          // 3) modulo  ← en çok bu sorulur

Örnek: boyut 5, front = 2, rear = 4 (C, D, E dolu). F eklenirse rear = (4+1) % 5 = 0, F 0. indekse yerleşir.

Tuzak: Dairesel dizide rear < front artık boşluk testi olamaz (yukarıdaki örnekte rear=0 < front=2 ama kuyruk dolu).

Bir yer boş bırakma yöntemi (slayt): front, ilk elemanı değil ilk elemandan bir önceki konumu gösterir; rear son elemanı gösterir.

Boş: front == rear
Dolu: front == (rear + 1) % size
Dezavantajı: dolu ve boşu ayırt etmek için dizide bir göz hep boş kalır, yani size kadar değil size−1 eleman tutulur.

Kendi dairesel kuyruğunu adım adım oynatmak için Araçlar sekmesine geç.

Kuyruk gerçekleştirme yöntemleri (6)

  1. Fiziksel model: front hep dizinin ilk konumunda. Silmede tüm elemanlar bir kaydırılır (yavaş).
  2. İki indeksli doğrusal dizi: front ve rear sürekli artar (yer israfı).
  3. Bir konumu boş bırakılan dairesel dizi: dolu ve boşu ayırmak için bir göz boş kalır.
  4. Boolean flag'li dairesel dizi: front/rear + dolu/boş bayrağı.
  5. Sayaçlı dairesel dizi: front/rear + eleman sayısı (count). count==0 boş, count==size dolu.
  6. Özel değerli dairesel dizi: boşluğu belirtmek için front/rear'a özel değer (ör. −1) atanır.

Temel fikir

Problemi aynı türden daha küçük problemlere bölüp onları çözerek asıl problemi çözmek. Özyinelemeli fonksiyon kendisini çağırır.

  • Temel durum (base case): fonksiyonun kendini çağırmayı bırakıp doğrudan sonuç döndürdüğü koşul. Yoksa sonsuz özyineleme ve stack overflow olur.
  • Özyinelemeli adım: problem küçültülüp fonksiyon tekrar çağrılır. Her çağrı temel duruma bir adım yaklaşmalıdır.
  • Çoğu özyinelemeli çözüm böl ve yönet (divide and conquer) stratejisini kullanır (ör. ikili arama: sözlüğü ikiye böl, uygun yarıda ara).
  • Özyineleme güçlüdür ama verimliliği garanti etmez.

Özyinelemeli çözüm için 4 soru

  1. Problemi aynı türden daha küçük problemler cinsinden nasıl tanımlarım?
  2. Her çağrı problemin boyutunu nasıl küçültür?
  3. Hangi örnek temel durum olarak kullanılabilir?
  4. Boyut küçüldükçe temel duruma ulaşılacak mı?

Dördüne de olumlu cevap varsa uygun bir tümevarım vardır. “Özyinelemeli düşünme” yerine “tümevarımsal düşünme” demek daha uygun olabilir.

Faktöriyel

int fact(int n) {          // ön koşul: n >= 0
    if (n == 0) return 1;  // temel durum
    else return n * fact(n-1);   // (A)
}
fact(3) = 3 * fact(2)
              = 2 * fact(1)
                    = 1 * fact(0)
                          = 1          ← temel durum
        → 1 → 1*1=1 → 2*1=2 → 3*2 = 6

fact(3) toplam 4 çağrı yapar: fact(3), fact(2), fact(1), fact(0). Her çağrı boyutu 1 azaltır; n negatif olmadığı için temel duruma her zaman ulaşılır.

Tuzak: fact(-1) ön koşulu bozar: n hiçbir zaman 0 olmaz, sonsuz özyineleme ve stack overflow olur. Negatif sayının faktöriyeli tanımsızdır.

Değişmez (invariant): algoritmanın belirli bir noktasında her zaman doğru olan koşul. fact'te: // n > 0, so n-1 >= 0. Thus fact(n-1) returns (n-1)!

Kutu izi (box trace)

Derleyicinin özyinelemeyi nasıl gerçekleştirdiğinin gösterimi. Her kutu kabaca bir etkinleştirme kaydına (activation record) karşılık gelir.

  1. Gövdedeki her özyinelemeli çağrıyı etiketle (A, B…): dönüş noktası belli olsun.
  2. Her çağrı için yeni kutu çiz: argümanların kopyası, çağrının döndüreceği değer için yer tutucu, fonksiyonun değeri ve yerel değişkenler.
  3. Çağıran kutudan yeni kutuya etiketli ok çiz.
  4. Fonksiyondan çıkarken kutunun üstünü çiz, ok boyunca geri dön, dönen değeri yerine yaz.

power(x, n)

int power(int x, int n) {
    if (n < 0) { cout << "Illegal argument"; exit(1); }
    if (n > 0) return power(x, n-1) * x;
    else       return 1;         // n == 0 temel durum
}
// power(2,3) → power(2,2)*2 → power(2,1)*2 → power(2,0)*2 → 1
//            → 1*2=2 → 2*2=4 → 4*2 = 8    (4 çağrı)

writeVertical: rakamları alt alta yaz

void writeVertical(int n) {
    if (n < 10) cout << n << endl;       // temel durum
    else {
        writeVertical(n / 10);           // önce son rakam hariç hepsi
        cout << (n % 10) << endl;        // sonra son rakam
    }
}
// writeVertical(123): 1, 2, 3 (alt alta)
Tuzak: cout özyinelemeli çağrıdan önce yazılırsa rakamlar ters çıkar (123 → 3, 2, 1). Çıktı sorularında çağrı ile yazdırmanın sırasına bak.

writeBackward: diziyi tersten yaz

void writeBackward(string s) {
    int length = s.size();
    if (length > 0) {
        cout << s.substr(length - 1, 1);       // son karakteri yaz
        writeBackward(s.substr(0, length - 1)); // geri kalanı tersten yaz
    }   // length == 0: temel durum, hiçbir şey yapma
}
// "cat" → "tac"

Dört soru: n uzunluğu n−1'e indirgenir. Temel durum boş dizi (hiçbir şey yapma). Her çağrıda uzunluk 1 azalır, temel duruma ulaşılır.

İkili arama (binary search)

  • Sıralı (doğrusal) arama: kolay ama verimsiz. Her başarısız testte 1 eleman elenir.
  • İkili arama: daha verimli ama dizi önce sıralanmış olmalı. Her başarısız testte kalan listenin yarısı elenir; adı buradan gelir.
int binarySearch(const int a[], int first, int last, int target) {
    int index;
    if (first > last) index = -1;                 // temel durum: yok
    else {
        int mid = first + (last - first) / 2;
        if (target == a[mid]) index = mid;        // temel durum: bulundu
        else if (target < a[mid])
             index = binarySearch(a, first, mid-1, target);   // X
        else index = binarySearch(a, mid+1, last, target);    // Y
    }
    return index;
}

Slayt örneği: a = 5 7 9 13 32 33 42 54 56 88 (indeks 0–9), hedef 33

firstlastmida[mid]Karar
0943233 > 32 → sağ yarı
5975433 < 54 → sol yarı
56533Bulundu: indeks 5

Temel durumlar: target == a[mid] (bulundu) ve first > last (yok, −1). mid = first + (last−first)/2, (first+last)/2 ile aynı sonucu verir ama büyük sayılarda taşmayı önler.

binarySearch2 (alternatif): temel durum first == last. Sağ yarı için mid dahil edilir: binarySearch2(a, mid, last, target).

maxArray: en büyük eleman (böl ve yönet)

maxArray(<1,6,8,3>) = max( maxArray(<1,6>), maxArray(<8,3>) )
maxArray(<1,6>) = max(1, 6) = 6     maxArray(<8,3>) = max(8, 3) = 8
sonuç = max(6, 8) = 8        // toplam 7 çağrı

Temel durum: dizide tek eleman varsa o elemandır.

Özyineleme ve verimlilik

  • Verimsizlik kaynakları: fonksiyon çağrısı ek yükü (yerel değişkenler, dönüş adresi vb. kayıt tutma) ve bazı algoritmaların doğasındaki verimsizlik.
  • binarySearch ve solveTowers (Hanoi) istisnadır; oldukça verimlidirler.
  • Kural: Özyinelemeli çözüm verimsizse ve açık, verimli bir yinelemeli (iterative) çözüm varsa özyinelemeyi kullanma.
  • Kuyruk özyinelemesi (tail recursion): özyinelemeli çağrının fonksiyonun yaptığı son işlem olması. writeBackward kuyruk özyinelemelidir ve kolayca while döngüsüne çevrilir.
void writeBackward(string s) {       // yinelemeli sürüm
    int length = s.size();
    while (length > 0) { cout << s.substr(length-1, 1); length--; }
}
Tuzak: fact kuyruk özyinelemeli değildir: çağrıdan sonra hâlâ n * çarpması yapılır. writeVertical da değildir: çağrıdan sonra cout var.
